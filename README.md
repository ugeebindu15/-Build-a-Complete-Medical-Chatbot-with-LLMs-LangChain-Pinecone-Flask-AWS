## 🧠 Problem Statement

Medical information is vast, unstructured, and scattered across documents. General-purpose LLMs hallucinate when answering domain-specific medical questions without grounding. This chatbot solves that by building a **RAG pipeline** on top of a real medical encyclopedia — so every answer is retrieved from verified content before being generated by GPT-4o.

## 🏗️ Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                      INGESTION PIPELINE                          │
│                                                                  │
│   Medical PDF                                                    │
│       ↓                                                          │
│   PyPDFLoader + DirectoryLoader                                  │
│       ↓                                                          │
│   RecursiveCharacterTextSplitter                                 │
│   chunk_size=500  ·  chunk_overlap=20                            │
│       ↓                                                          │
│   HuggingFace all-MiniLM-L6-v2  →  384-dim embeddings           │
│       ↓                                                          │
│   Pinecone Vector Index (cosine similarity · AWS Serverless)     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      QUERY PIPELINE (RAG)                        │
│                                                                  │
│   User Question                                                  │
│       ↓                                                          │
│   HuggingFace Embeddings  →  Query Vector                        │
│       ↓                                                          │
│   Pinecone Similarity Search  →  Top k=3 Chunks                  │
│       ↓                                                          │
│   LangChain RAG Chain  →  Context + Query  →  GPT-4o             │
│       ↓                                                          │
│   Grounded Medical Response  →  Flask Chat UI                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                   DEPLOYMENT & CI/CD                             │
│                                                                  │
│   GitHub Push                                                    │
│       ↓                                                          │
│   GitHub Actions  →  Docker Build  →  Push to AWS ECR           │
│       ↓                                                          │
│   AWS EC2  →  Pull Image  →  Run Container  →  Live on Port 8080 │
└─────────────────────────────────────────────────────────────────┘
```

## 🛠️ Tech Stack

| Layer | Technology | Purpose |
|---|---|---|
| Document Loading | LangChain PyPDFLoader + DirectoryLoader | Ingest medical PDF |
| Text Splitting | RecursiveCharacterTextSplitter | 500-token chunks, overlap=20 |
| Embeddings | HuggingFace all-MiniLM-L6-v2 | 384-dim semantic vectors |
| Vector Database | Pinecone (cosine · AWS Serverless) | Store & retrieve embeddings |
| LLM | OpenAI GPT-4o | Context-aware response generation |
| RAG Orchestration | LangChain RAG Chain | Retrieval + generation pipeline |
| Web App | Flask | REST API + Chat UI |
| Containerization | Docker | Reproducible deployment |
| Container Registry | AWS ECR | Store Docker images |
| Cloud Hosting | AWS EC2 | Serve the application |
| CI/CD | GitHub Actions | Auto build + deploy on every push |

---

## ✨ Key Features

- **RAG Pipeline** — Answers grounded in a real medical encyclopedia, eliminating LLM hallucinations
- **Semantic Search** — HuggingFace embeddings + Pinecone cosine similarity retrieves the most relevant chunks
- **Top-k Retrieval** — k=3 most relevant chunks passed as context to GPT-4o for every query
- **Production CI/CD** — Every `git push` triggers GitHub Actions → Docker build → ECR push → EC2 auto-deploy
- **Fully Containerized** — Docker ensures consistent behavior from local dev to AWS production
- **Grounded System Prompt** — GPT-4o is constrained to answer only from retrieved context

## 🚀 How to Run

### Prerequisites
- Python 3.8+
- Docker Desktop
- Pinecone account (free tier works)
- OpenAI API key
- AWS account (EC2 + ECR)

### Step 1 — Clone the repo
```bash
git clone https://github.com/ugeebindu15/-Build-a-Complete-Medical-Chatbot-with-LLMs-LangChain-Pinecone-Flask-AWS
cd -Build-a-Complete-Medical-Chatbot-with-LLMs-LangChain-Pinecone-Flask-AWS
```

### Step 2 — Create virtual environment and install dependencies
```bash
conda create -n medibot python=3.10 -y
conda activate medibot
pip install -r requirements.txt
```

### Step 3 — Set environment variables
Create a `.env` file in the root:
```
PINECONE_API_KEY=your_pinecone_api_key
OPENAI_API_KEY=your_openai_api_key
```

### Step 4 — Build the Pinecone index (run once)
```bash
python store_index.py
```
This loads the medical PDF, chunks it, generates embeddings, and stores them in Pinecone.

### Step 5 — Run the Flask app locally
```bash
python app.py
```
Visit `http://localhost:8080` to chat with the bot.

### Step 6 — Run with Docker
```bash
docker build -t medical-chatbot .
docker run -p 8080:8080 \
  -e PINECONE_API_KEY=your_key \
  -e OPENAI_API_KEY=your_key \
  medical-chatbot
```

## 🏛️ Architecture Decisions

**Why RAG over fine-tuning?**
RAG retrieves answers from a fixed, verified knowledge base at query time — no retraining needed, answers stay grounded in source content, and the knowledge base can be updated independently of the model.

**Why HuggingFace embeddings over OpenAI embeddings?**
`all-MiniLM-L6-v2` is free, fast, lightweight (384 dims), and produces high-quality semantic embeddings — ideal for a cost-efficient production pipeline.

**Why Pinecone over a local vector store?**
Pinecone is fully managed, serverless, and scales to millions of vectors without infrastructure overhead — perfect for a production deployment on AWS.

**Why Docker + ECR + EC2 over serverless?**
The Flask app + embedding model load requires persistent compute. EC2 with Docker gives full control over the runtime environment, while ECR ensures the exact same image runs in dev and production.
